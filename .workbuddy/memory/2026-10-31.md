### DEV-003 关键结论（可复用）

1. **R 键失效的真实根因是中文输入法**：`e.key === 'r'` 在 IME 激活时拿到的是 `'Process'`（`isComposing=true`）。凡面向中文用户的网页键盘交互，一律改 `e.code` 物理键位。
2. **踩踏判定**：`player.vy > 1.2 && playerBottomPrev <= e.y + e.h * 0.6`，需用上一帧脚底位置，否则会漏判。
3. **必须加受伤硬直 `hurtStun`**：否则「侧碰被弹飞 → 落回同一只怪头上 → 踩死 → 奖励抵消惩罚」，惩罚形同虚设。这是逐帧追踪才发现的逻辑漏洞，不是代码报错。
4. **测试方法本身也会错**：DEV-001 曾因金币与角色同为橙色而误判「跳跃失败 0px」。定位像素时必须用角色专属配色。

### 建立的可复用测试手段

- Chrome DevTools Protocol：`--headless=new --remote-debugging-port` + WebSocket 驱动 `Runtime.evaluate` / `Input.dispatchKeyEvent` / `Page.captureScreenshot`
- **状态探针注入法**：读源文件 → 字符串替换注入 `window.__p` getter → 写临时 `.probe*.html` → 测试 → 删除。保证磁盘成品文件不被测试代码污染
